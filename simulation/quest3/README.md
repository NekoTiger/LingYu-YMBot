# Quest 3 接入包

**2026-11-17 文献改进版**：新增依据工作空间边界的前后跟随、带载动作分配、回中确认及接管，独立入口为根目录 `启动Quest3文献改进版.cmd`（8767）。见 [使用与验收说明](文献改进版使用说明.md)。它是独立预实验，不自动替换原正式方案。

**11 月 21 日答辩的当前安排**见 [答辩推进与实验安排](11月21日答辩推进与实验安排.md)。新增 `启动Quest3对照实验.cmd` 使用端口 8766，提供两模式、两场景和正式试次计时。先用 P00 试跑。原 8765 入口继续作为自由操作入口。

2026-11-16 已收到 Quest 3 浏览器与两只 Touch Plus 控制器的真实输入，设备接入已完成初次试用。下文早期“实机待验证”记录指接口首次开发时的验收状态；新版辅助模式与实验流程仍需佩戴试跑，正式对照数据尚待采集。

该入口把 Quest 浏览器的双控制器位姿送入电脑上的 MuJoCo，头显内呈现立体仿真，默认并肩视角（与机器人同向），可切换对面/身后视角。物体仍受重力、摩擦和接触力作用，网络接口只接收操作意图，不接受关节状态或货物位置覆盖。

**当前状态：电脑端已准备，Quest 3 实机测试待设备到场。** 通信回归和抓取检查使用合成输入；不能写成人类 VR 实验，也不能据此宣布已完成真机闭环。这里的“真机待测”指 Quest 头显，不要求接实体机器人。

## 到场前准备

- Quest 3、左右两只 Touch Plus 控制器、有数据传输功能的 USB 线。
- 在设备所属 Meta 账号下开启开发者模式；接线后由佩戴者在头显里允许 USB 调试。开发者账号及设备权限需要设备持有人操作。数据线建议 2–3 m 留出转身余量；画面视角可虚拟调整，无需绕机器人走动。
- 这台电脑已安装项目内的 Android Platform Tools、Python 服务依赖及本地 Three.js。无需改系统 PATH，也无需 Unity 工程。
- 当前采用 **USB ADB 端口转发**；无需相同 Wi-Fi。不要把 `http://电脑局域网IP:8765` 当作可用的 WebXR 接入方式。服务只监听本机。

## 启动顺序

1. 在项目根目录双击 **启动Quest3仿真.cmd**，保留窗口。电脑浏览器可以打开 `http://localhost:8765` 观察三维状态。
2. USB 连接 Quest，完成头显里的调试授权，再双击 **连接Quest3_USB.cmd**。该脚本只给选定设备设置 `tcp:8765` 转发；多台 Android 设备时会要求指定 Quest 序列号。
3. 在 **Quest Browser** 打开 `http://localhost:8765`，待场景加载完，点击“进入 VR”。首次传输包含约 30 万三角面的模型，加载时间和头显渲染帧率需要实测。
4. 先松开双侧握键，然后同时握住。当前控制器位置会对应机器人当前双手位置，避免进入时跳变。
5. 结束时先退出 VR，再在电脑服务窗口按 **Ctrl+C**。这会写完记录。不要直接关闭终端窗口，以免最后一个数据块尚未落盘。

断线后端口转发可能需要重新运行；不必重复安装依赖。若出现 `unauthorized`，查看头显内的授权窗口；`no device` 则先核对数据线、开发者模式和设备连接状态。

## 操作

|输入|效果|
|---|---|
|同时按住左右侧握键|离合接通，按相对位移控制双手；每次重新握住都会标定|
|松开任一侧握键|停止底盘速度指令，保持手臂关节和当前夹爪闭合量|
|双手共同抬高、前伸、左右移动|移动托盘中心；位移比例 0.8，目标速度限制 12 cm/s|
|改变双手连线的水平方向|共同偏航；相对底盘限制约 ±20°，保持托盘水平和 60 cm 双手间距|
|离合接通时改变双食指扳机深度|同步夹爪；压下趋于夹紧，松开趋于张开。两侧扳机取均值|
|左摇杆上下、左右|前进后退、转向；最大约 0.16 m/s、0.4 rad/s，有加速度限制|
|未握离合时右摇杆|调整视角：左右绕机器人原地旋转（机器人位置不动），上下推远／拉近；只改画面，不影响控制映射|
|未握离合时左 Y|在 并肩 / 身后 / 对面 三种视角间切换，切换后回到该视角默认距离|
|右 B / 网页“停止”|锁定停止状态|
|松开双握键后按左 X / 网页“恢复”|解除停止，再重新握住离合|
|电脑网页“重置场景”|关闭当前记录，开启新的会话；必须先松开双握键|

**夹爪在重新握住离合时保持原状。** 重新握住本身不会因为扳机已经松开而丢下物体；此后改变扳机深度才会改变夹爪目标。如果夹爪闭合而扳机已在松开位置，需要先压下、再松开扳机才能打开。

头部水平方向用于标定人的“前方”，人的前伸映射到机器人前方，人的左移映射到机器人左方。默认并肩视角：机器人站在你的右前方、与你的朝向一致，你前伸就是机器人前伸，画面方向与直觉一致。开始操作前（松开双握键时）用右摇杆绕机器人旋转视角、左 Y 切换视角；机器人锚定在原地不动，调整只改变渲染，不用绕机器人走动。可转头、走动观察。按键按 WebXR `xr-standard` 编号读取；Quest 的 B/X/Y 实际映射、追踪恢复及视野清晰度都必须在到场测试时核对。页面“停止/恢复”可由电脑旁的队员操作。切出 VR 或追踪原点发生变化会停止，需要重新恢复、标定。

## 首次到场验收：约 15 分钟

由一名佩戴者和一名电脑观察员完成，先只做小幅动作。

1. **连通与坐标**：页面进入立体视图；检查抬高、前伸、左右方向正确，双手数据年龄通常低于 100 ms。记录浏览器版本、控制器 profiles、可见卡顿和头显实际帧率（若无法测量就写未测）。
2. **离合与停止**：握住时移动；松开任一侧后停止；保持物体时重新握住不应自动张爪；按 B 停止、松开双握键后按 X 恢复。拔掉 USB 后确认底盘命令停止，重连不能直接恢复运动。
3. **第一次抓放**：从初始悬空位置缓慢下降约 9 cm 对准两侧把手，压下双扳机，等待夹紧；抬高约 12 cm，保持 2 s；下放到源台后松开扳机，抬手撤离。观察员标注成功或失败，不强求首次就成功。
4. **带载小范围移动**：抓起后轻推摇杆后退约 5–8 cm，回到原位置，再放回源台。通过后再尝试原场景目标台搬运。
5. 至少留下 **3 次完整试次**，包含失败和中断记录。匿名操作者编号填 P01/P02 即可，不需要姓名。用电脑页面“开始试次 / 标注成功 / 标注失败”记录；未结束的试次不能重复开始。

在 [设备验收记录模板.md](设备验收记录模板.md) 填写实际结果。没有头显时这些项保持“待测”。不要用这里的短距离接口检查替代 V3 的复杂任务实验。

## 记录与回放

每次启动、重置都会新建 `sessions/日期时间_随机编号/`。测试脚本的记录在 `outputs/`，不混入真人会话。

|文件|内容|
|---|---|
|scene.xml|该次使用的 MuJoCo 模型，网格路径仍指向本项目资产|
|raw_webxr.jsonl|原始头部/双手位置、xyzw 四元数、按键、序号、客户端采集时间及服务器接收时间|
|events.jsonl|标定、停止、断线、拒绝输入、试次、观察员结果标记及视角调整|
|states_0000.npz 等|100 Hz 控制步的 qpos、qvel、执行器命令、双手目标、启用状态及仿真/墙钟时间|
|session.json|数据源、帧数、时长、设备声明、来源历史；`hardware_verified` 默认 false，不自动把浏览器自报设备当验收|

`source=webxr_live` 表示浏览器路径；测试用 `synthetic_transport_test`。若同一会话出现多种来源，明确标注 `mixed_sources`。成功按钮只是观察员注释，不能代替最终接触、释放和稳定性核验。

在项目根目录 PowerShell 执行（把路径替换成实际会话）：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m simulation.quest3.review_session "simulation/quest3/sessions/会话目录" --video
```

将生成三张检查图、`review.json` 和 `review/replay.mp4`。回放按保存的仿真时间播放，不重新运行控制，也不是头显录屏。原始墙钟时间保留，可另行评估实时性。真人试次还应由队员保留一段佩戴操作录像，以对应原始记录。

## 自动验证与依赖

```powershell
.\.venv\Scripts\python.exe -m unittest simulation.quest3.test_protocol -v
node simulation/quest3/web/test_input.mjs
.\.venv\Scripts\python.exe -X utf8 -m simulation.quest3.check_integration
.\.venv\Scripts\python.exe -X utf8 -m simulation.quest3.check_manipulation
```

两项物理检查写入新目录，不覆盖历史结果；只运行本地仿真，不连接头显。通信检查包括实际 HTTP/WebSocket、单控制者、坐标和物理运动、松手/追踪丢失/断流停止、重新握住不松夹爪、停止恢复、乱序包和记录落盘。抓取检查使用合成手部输入验证接触夹持、抬升、轮地移动、回到源台、释放及物件留存。

本次结果见 [电脑端验收结果](电脑端验收结果.md)。离线抓取检查注入合成时钟，其 `wall_elapsed` 不表示实际运行耗时；只有实时服务和通信检查的墙钟记录适合评估本机实时性。

搬到新电脑需先恢复原项目的 MuJoCo/Mink 环境，再安装 `requirements-extra.txt`，在 `web/` 运行 `npm ci --ignore-scripts`。本机已安装，不必重装。项目内 Platform Tools 首次可运行 `install_adb.ps1` 下载，来源及 SHA-256 存在 `tools/download.json`，发布者许可保留在工具包里。Three.js 版本 0.180.0，MIT 许可在 `web/node_modules/three/LICENSE`；这是输入接口实现，不冒称复现了某篇论文的完整系统。

## 当前能力边界

- 提供可调整的立体仿真视图（并肩/对面/身后），不是机器人相机视频；没有眼动、颈部跟随或实体机器人控制。
- 保留原始 6DoF 位姿，但控制映射约束为托盘中心、共同偏航和同步平行夹爪；没有独立腕部 6DoF 或灵巧手手指映射。
- 250 ms 没有新数据、追踪丢失或网络断开后停止命令，并要求重新松开再握住。命令停止不等于物理底盘瞬间静止。
- 当前直接控制场景有静态障碍；人负责路线与操作。V3 的动态障碍停车、接触放置反馈和独立种子批量结果仍在原研究入口，这个新入口尚未获得同样的验证。
- Windows 服务使用成对申请/释放的 1 ms 定时精度改善 100 Hz 调度；记录真实墙钟时间，出现慢机时不能把仿真时间当实时帧率。
- Quest 浏览器加载、双目显示、按键映射、手柄追踪抖动、实际延迟和持续帧率尚未实机验证。前端当前通过模块语法与纯输入逻辑检查，未做头显或浏览器视觉验收。

## 接口依据

- [Meta：Browser Remote Debugging](https://developers.meta.com/vr/documentation/web/browser-remote-debugging/)：开发者模式、USB 调试及 `adb reverse`。
- [W3C：WebXR Gamepads Module](https://www.w3.org/TR/webxr-gamepads-module-1/)：`xr-standard` 按键/摇杆定义。
- [MDN：XRInputSource.gripSpace](https://developer.mozilla.org/en-US/docs/Web/API/XRInputSource/gripSpace)：控制器握持位姿。
- [Android：Access a local server](https://developer.android.com/develop/ui/views/layout/webapps/access-local-server)：通过 USB 访问开发机服务。
